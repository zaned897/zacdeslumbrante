Diagrama 1

Arquitectura general

Los tres agentes no hablan entre sí por una red: se coordinan a través de archivos del repo que los tres leen. Claude es el único que llama a otro agente directamente, cuando pide una revisión a Codex con el plugin.

Ejemplo real: la issue #12, [mock] Eventos culturales, que toca backend Python y frontend. Cada flecha es un mensaje o comando; las cajas sobre una línea son trabajo interno de ese actor.

Diagrama 5 · flujo de decisión

Herramientas justo a tiempo

Así la suite se acuerda por ti de las ideas pendientes, como los avatares o los edificios isométricos, sin instalar nada antes de tiempo.

Diagrama 6 · tubería de calidad

Barreras de calidad

Cada cambio pasa por cuatro filtros antes de llegar a main. Los dos primeros corren solos en tu máquina; los agentes también pasan por ellos.

Diagrama 7 · flujo de peticiones

La app en ejecución

Qué pasa cuando el navegador pide algo. Express se queda como puerta de entrada; las features nuevas viven en Python detrás de /api/py.

Diagrama 8 · línea de tiempo

Relevo cuando se acaba la cuota

Con Claude Pro, ChatGPT Plus y Antigravity gratis, alguno se quedará sin cuota a media tarea. La skill relay deja el contexto por escrito para que otro agente siga sin releer todo.

Parte II

Instalación por etapas, con pruebas

Nueve etapas en orden. Cada una termina con una prueba automática (verify.sh) y, cuando hace falta, pruebas manuales. No avances si la prueba muestra ✗: la tabla «Si falla» de cada etapa dice qué hacer. Marca cada etapa al terminarla; el avance se guarda en este navegador.

0 de 9 etapas

Lugar de cada comando: PowerShell solo en la etapa 1. Todo lo demás en Warp con Git Bash, salvo lo marcado como dentro de claude (escrito en la sesión de Claude Code) o navegador.

0

Seguridad primero

5 minnavegador + editor

El .env.example de tu repo público trae una llave real de Google Maps. Cualquiera puede usarla y cargarla a tu cuenta.

Pasos

  1. En Google Cloud → Credenciales, crea una llave nueva y restríngela: Referentes HTTP = http://localhost:*/* (y tu dominio cuando exista); APIs = solo Maps JavaScript API.

  2. Borra o desactiva la llave vieja (la que empieza con AIzaSyCxLb…).

  3. En .env.example deja el placeholder; la llave nueva va solo en .env (lo harás en la etapa 3):

    VITE_MAPS_API_KEY="MY_MAPS_API_KEY"

Prueba

  • En Credenciales, la llave vieja ya no aparece o dice «Deshabilitada».
  • La nueva muestra el ícono de restricciones (referentes + 1 API).
  • La comprobación automática llega en la etapa 3: ✓ .env.example sin llaves reales.

Herramientas

20 minPowerShell, luego Warp

Pasos

  1. Descomprime suite-v5-zacdeslumbrante.zip en C:\dev\suite-v5 (temporal; en la etapa 3 lo copias al repo).

  2. Abre PowerShell normal (no admin) y corre el instalador:

    PowerShellcd C:\dev\suite-v5 Set-ExecutionPolicy -Scope Process Bypass .\scripts\windows-bootstrap.ps1

    Instala con winget Git (incluye Git Bash), Node LTS, GitHub CLI, uv, Bun y Warp; luego Claude Code y Codex. Puedes correrlo varias veces sin problema.

  3. Activa Configuración → Sistema → Para programadores → Modo de desarrollador (permite symlinks sin admin).

  4. Instala Antigravity desde antigravity.google.

  5. Abre Warp → Settings → Features → Session → Default shell: Git Bash. Settings → Appearance → Tabs → Use vertical tab layout. Cierra y abre Warp.

Ensayo general

45–60 mintodos los agentes

Una feature pequeña con backend y frontend en paralelo, para probar worktrees, Antigravity, relevo y revisión cruzada antes de trabajar en serio.

Pasos

  1. dentro de claudeCon gh-issues, crea una issue [mock] de eventos culturales: GET /api/py/events con 5 eventos de ejemplo y una tarjeta de evento con badge "Demo" en el panel lateral.
  2. pestaña 4./scripts/worktrees.sh mock/N-eventos-api mock/N-eventos-ui

  3. Pestaña 1: cd ../zacdeslumbrante-back && claude → «usa orchestrate, tu parte de la issue #N».

  4. Antigravity: abre C:\dev\zacdeslumbrante-front → «usa orchestrate, tu parte de la issue #N». Servidor del front con PORT=3001 ./scripts/dev.sh.

  5. Prueba de relevo (a propósito, a mitad del backend):

    dentro de claudeUsa relay para pasarle esto a Codex.

    Pestaña 3: cd ../zacdeslumbrante-back && codex → «usa relay para recibir la issue #N».

  6. Revisión cruzada, PRs, CI y merge de las dos ramas. Limpieza:

    pestaña 4git worktree remove ../zacdeslumbrante-back ../zacdeslumbrante-front
